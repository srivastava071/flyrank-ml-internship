Identifying Content at Risk of Decline

An applied machine learning study using pseudonymized content performance data to create a decision-support workflow for content refresh prioritization.

Author: Himanshu Srivastava

Abstract

This study asks whether historical content-performance signals can help identify content that may be at risk of decline and therefore deserve human review. The analysis uses the FlyRank ML Internship dataset and evaluates content using historical performance, search-query visibility, and content-age signals. A Random Forest model was evaluated using both a row-random split and a client-grouped split to test whether performance remained directional when content from the same client was kept together. The measured average precision was 0.4131 under the client-grouped evaluation, compared with 0.3874 under the row-random split, with a test-set positive rate of 23.87% for the grouped evaluation. The resulting output is intended as decision-support for prioritizing human review, not as an automated decision about whether content will decline.

1. Introduction / Problem

Content teams manage large numbers of pages and cannot manually review every page with the same level of attention. A useful decision-support system can help surface content that deserves earlier human investigation.

The question explored here is: Can historical content-performance signals help rank content for potential refresh or review?

The intended decision is prioritization. The model does not decide whether a page should be changed. Instead, it provides a ranked queue that an editor or analyst can inspect.

2. Data

The analysis was developed using the FlyRank ML Internship dataset. The internship data contains pseudonymized content-performance information and client identifiers used for grouping and evaluation.

The modeling workflow used historical 30-day performance signals, search-query visibility measures, and content age.

Public-safety principle: Client and content identifiers were treated as grouping or reference fields and were not used as predictive model features.

Outcome-derived fields were deliberately excluded from the model. In particular, trend-related fields were not used as predictors because they are connected to the target definition.

3. Methodology

Features

  • Previous 30-day impressions
  • Previous 30-day clicks
  • Previous 30-day average position
  • Visible query count
  • Top-query share
  • Content age in days

Validation

Two validation designs were compared. The first used a row-random split. The second used a client-grouped split so that content from the same client did not appear across both training and test sets.

The grouped evaluation provides a more conservative test of whether the model's ranking behavior transfers to clients not represented in training.

Leakage audit

The final feature set was checked for known label-derived fields, outcome fields, and identifier features. The audit found no known label-derived or outcome columns in the final model features.

4. Results

0.3874 Random-split Average Precision
0.7436 Random-split ROC-AUC
0.4131 Client-grouped Average Precision
0.7315 Client-grouped ROC-AUC
Measured result: The client-grouped evaluation produced an average precision of 0.4131. Its test positive rate was 23.87%.

The difference between the two validation designs is itself useful: it shows why validation design matters when multiple observations belong to the same client.

These results are directional evidence for ranking and prioritization, not evidence of causality or guaranteed future performance.

5. Limitations & Honest Framing

  • The model identifies statistical patterns in the available dataset; it does not establish causal relationships.
  • A high model score does not mean that a page will definitely decline.
  • The ranked queue should be reviewed by a human before any content change is made.
  • Model performance may change when data distributions, search behavior, or content environments change.
  • The analysis should not be interpreted as predicting a search engine's internal algorithm or future ranking decisions.

6. Ranked Recommendations

1. Review high-priority content first

Use the model's ranking as a triage queue so analysts can focus attention on content with higher measured decline probability.

2. Investigate recent performance changes

Review recent impressions, clicks, and average-position signals alongside the model score before deciding whether an update is appropriate.

3. Check search visibility

Low query visibility can provide an additional reason for an analyst to investigate a page's search coverage.

4. Consider content age

Older content can be reviewed for freshness, relevance, and whether its current information still matches the user's needs.

Important: These recommendations are decision-support actions. They should not be automated into publishing, deletion, or major content changes without human review.
