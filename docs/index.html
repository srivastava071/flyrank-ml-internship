Identifying Content at Risk of Decline

An applied machine learning study using pseudonymized content-performance data to create a decision-support workflow for content refresh prioritization.

Author: Himanshu Srivastava · 2026

Abstract

This study asks whether historical content-performance signals can help identify content that may be at risk of decline and therefore deserve human review. The analysis uses the FlyRank ML Internship dataset and evaluates content using historical performance, search-query visibility, and content-age signals. A Random Forest model was evaluated using both a row-random split and a client-grouped split to examine whether the observed ranking signal transferred when content from the same client was kept together. The measured Average Precision was 0.4131 under the client-grouped evaluation, compared with 0.3874 under the row-random split, while the grouped test set had a positive rate of 23.87%. The resulting output is intended as decision-support for prioritizing human review, not as an automated decision about whether content will decline.

1. Introduction / Problem

Content teams manage large numbers of pages and cannot manually review every page with the same level of attention. A useful decision-support system can help surface content that deserves earlier human investigation.

The question explored here is:

Can historical content-performance signals help rank content for potential refresh or review?

The intended decision is prioritization. The model does not decide whether a page should be changed. Instead, it produces a ranked queue that an editor or analyst can inspect.

This framing treats machine learning as a way to support limited human attention rather than as an automated content decision-maker.

2. Data

The analysis was developed using the FlyRank ML Internship dataset. The internship data contains pseudonymized content-performance information and client identifiers used for grouping and evaluation.

The modeling workflow used historical 30-day performance signals, search-query visibility measures, and content-age information.

Model features

  • Previous 30-day impressions
  • Previous 30-day clicks
  • Previous 30-day average position
  • Visible query count
  • Top-query share
  • Content age in days

Excluded information

Outcome-derived fields were deliberately excluded from the model. In particular, trend-related fields were not used as predictors because they are connected to the target definition.

Client and content identifiers were treated as grouping or reference fields and were not used as predictive model features.

Public-safety principle: No client-identifying details or private search queries are presented in this research artifact.

3. Methodology

Model

A Random Forest classifier was used to estimate which content items should receive higher priority for review based on the available historical signals.

Validation design

Two validation designs were compared.

The first used a row-random split. The second used a client-grouped split so that content from the same client did not appear across both training and test sets.

The grouped evaluation provides a different and more stringent test of whether the observed ranking behavior transfers to clients not represented in training.

Leakage audit

The final feature set was checked for known label-derived fields, outcome fields, and identifier features. The audit found no known label-derived or outcome columns in the final model features.

The validation workflow also treated client identifiers as grouping variables rather than predictive inputs.

Base-rate context

The client-grouped test set had a positive rate of 23.87%. The measured Average Precision of 0.4131 was above this prevalence baseline, providing directional evidence of ranking signal in this evaluation.

What changed across validation designs?

The row-random split measured an Average Precision of 0.3874, while the client-grouped evaluation measured 0.4131. ROC-AUC changed from 0.7436 to 0.7315.

The difference between validation designs is itself informative: it demonstrates why the choice of split matters when multiple observations belong to the same client.

Interpretation: These measurements provide directional evidence for ranking and prioritization. They do not establish causality or guarantee future performance on individual content items.

5. Limitations & Honest Framing

  • The model identifies statistical patterns in the available dataset; it does not establish causal relationships.
  • A high model score does not mean that a page will definitely decline.
  • The ranked queue should be reviewed by a human before any content change is made.
  • Model performance may change when data distributions, search behavior, or content environments change.
  • The analysis should not be interpreted as predicting a search engine's internal algorithm or future ranking decisions.
  • The evaluation measures performance on the available validation population and should not be treated as a guarantee of production performance.

6. Ranked Recommendations

1. Review high-priority content first

Use the model's ranking as a triage queue so analysts can focus attention on content with higher measured decline probability.

2. Investigate recent performance changes

Review recent impressions, clicks, and average-position signals alongside the model score before deciding whether an update is appropriate.

3. Check search visibility

Low query visibility can provide an additional reason for an analyst to investigate a page's search coverage.

4. Consider content age

Older content can be reviewed for freshness, relevance, and whether its current information still matches the user's needs.

Human-review rule: These recommendations are decision-support actions. They should not be automated into publishing, deletion, or major content changes without human review.
